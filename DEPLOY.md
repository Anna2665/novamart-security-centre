# Deploying NovaMart (Netlify pages + Render API)

```
 browser ──► Netlify  (the shop and the Security Centre pages: static files)
    │
    └──────► Render   (the FastAPI server: login, shop, attacks, live feed, database)
```

Netlify cannot run the Python server, so the two halves are hosted separately and the pages are told where the API lives.

## 1. API on Render
`render.yaml` describes the service. Environment variables (Render → the service → Environment):

| Variable | Value |
|---|---|
| `CORS_ORIGINS` | the Netlify address, e.g. `https://novamart-security-centre.netlify.app` |
| `DEMO_EMAIL` | the mailbox that receives staff sign-in codes |
| `RESEND_API_KEY` | key from resend.com (create the account with the same address as `DEMO_EMAIL`) |
| `OTP_DEV_ECHO` | `false` once e-mail works; `true` shows codes on screen instead |
| `CG_ADMIN_PASSWORD`, `CG_ANALYST_PASSWORD`, `CG_VIEWER_PASSWORD`, `CG_SHOPPER_PASSWORD` | generated by Render; read them in the same screen |

Free Render servers block outgoing SMTP, so e-mail goes over HTTPS (Resend) instead of Gmail SMTP. They also sleep when idle (first request takes about a minute) and the SQLite data resets on restart, which is fine for a demo.

## 2. Pages on Netlify
`netlify.toml` builds `frontend/`. Set one variable (Netlify → Project configuration → Environment variables):

| Variable | Value |
|---|---|
| `VITE_API_URL` | the Render address, e.g. `https://novamart-api.onrender.com` |

The same address must appear in `connect-src` (https and wss) in the `Content-Security-Policy` header in `netlify.toml`.

## 3. Pages you can open
| Page | Address |
|---|---|
| Shop | `/#/` |
| Customer sign-in / sign-up | `/#/signin`, `/#/register` |
| Cart, checkout, orders, account | `/#/cart`, `/#/checkout`, `/#/orders`, `/#/account` |
| Security Centre sign-in | `/#/soc` |
| Attack Lab | `/#/soc/attacks` |
| Guided Demo | `/#/soc/guide` |

Running locally is unchanged: `python run.py` serves everything on one port.
